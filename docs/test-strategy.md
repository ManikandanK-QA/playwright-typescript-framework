# Test strategy

## Approach

Risk-based, layered coverage over two public demo systems:

- **SauceDemo** (`https://www.saucedemo.com`) — UI, authentication, cart, checkout.
- **Restful Booker** (`https://restful-booker.herokuapp.com`) — REST, token auth, CRUD.

Both are stable, documented, credential-free demo targets, which keeps the
repository clone-and-run while still exercising real flows.

## Coverage matrix

| Layer | Area | Scenarios | Tag |
| --- | --- | --- | --- |
| UI | Authentication | valid sign-in, locked-out user, wrong password, missing username, missing password | `@smoke`, `@ui` |
| UI | Catalogue | six products listed, price sort ascending, add/remove with badge sync | `@smoke`, `@ui` |
| UI | Cart | contents, removal, continue shopping | `@ui` |
| UI | Checkout | end-to-end purchase, mandatory postal code | `@smoke`, `@ui` |
| API | Auth | token issued, invalid credentials rejected | `@smoke`, `@api` |
| API | Booking CRUD | create + read, name filter, full update, partial update, delete + verify 404 | `@smoke`, `@api` |
| API | Negative | unknown id, write without token, invalid create payload | `@api` |
| A11y | Login page | axe-core WCAG 2.0/2.1 A & AA, critical violations block | `@a11y` |

## Tags

| Tag | Intent | Command |
| --- | --- | --- |
| `@smoke` | 5-minute pre-merge confidence | `npm run test:smoke` |
| `@regression` | full functional sweep | `npm run test:regression` |
| `@ui` / `@api` / `@a11y` | layer isolation | `--project=...` |

Tags are applied with Playwright's `tag` option, so they appear in the HTML,
JUnit and Allure reports without polluting test titles.

## Test data

- Static demo identities live in `src/data/users.ts` and are parameterised; the
  negative login matrix is data-driven.
- API payloads are generated by `buildBooking()` (faker) and overridden only
  where the assertion depends on a value. Tests never share mutable fixtures.
- Each API test owns the records it creates; teardown deletes them.

## Determinism rules

1. No `waitForTimeout`. Web-first assertions and actionability checks only.
2. No assertions inside page objects. A failure points at the spec line.
3. No cross-test ordering. API specs are independent and parallel-safe.
4. No hardcoded URLs in specs; base URLs come from validated config.
5. Retries are a CI safety net (2 on CI, 0 locally), never a substitute for
   fixing flakiness. A test that only passes on retry is a defect.

## Explicit non-goals

- Load, stress and soak testing — separate performance repository.
- Visual pixel comparison — `advanced-playwright-labs`.
- Manual/exploratory charters — documented outside code.
- Third-party payment or email integrations — out of scope for demo targets.

## Exit criteria for a change

- `npm run validate` passes (typecheck, lint, format).
- Affected project passes locally on Chromium.
- New behaviour has at least one happy path and one negative or boundary case.
- No new arbitrary waits, no new hardcoded environment values.
